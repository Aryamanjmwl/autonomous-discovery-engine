# ADE v0.1.0 Technical Preview

Release date: 2026-07-22

## Scope

ADE v0.1.0 Technical Preview is a local-first release for exploratory visual
review. It produces candidate anomalies, candidate concepts, and candidate
temporal changes as review-prioritization signals. Every candidate finding
requires human review.

## What is included

### Visual workflows

- Explicit local image-folder analysis with deterministic patch extraction,
  representation, ranking, and report generation.
- Candidate anomaly and candidate concept evidence with stable review targets.
- Reference memory and optional artifact-backed reference-score evidence.
- Optional spatial anomaly maps, fitted calibration summaries, candidate
  operating points, and benchmark validation artifacts.
- DINOv2 and FAISS integrations kept behind optional provider boundaries; neither
  is enabled by default or required by the lightweight installation.

### Temporal workflows

- Explicit temporal manifests with deterministic observation ordering.
- Adjacent and baseline comparison strategies for candidate temporal changes.
- Immutable temporal artifacts with SHA-256 integrity validation.
- JSON, Markdown, and HTML temporal reports with optional real patch evidence.
- Candidate change events remain review-prioritization signals and require human
  review.

### ADE Studio

- A local backend and connected frontend for real validated local reports.
- Standard visual and temporal report summaries, findings, provenance, warnings,
  and limitations.
- Honest empty and warning states when valid local evidence is unavailable.
- No fabricated report values, charts, or temporal evidence in connected mode.

### Deterministic demos

- A deterministic image-folder demo workflow.
- Three generated local temporal demo sequences with canonical manifests.
- End-to-end temporal verification covering manifest, analysis, artifact, JSON,
  Markdown, and HTML output.
- Synthetic demo data is generated locally and remains outside release source
  files.

## Validation status

Release preparation verifies linting, static typing, the complete Python test
suite, the local demo workflow, the deterministic temporal demo, and the Studio
frontend typecheck and production build. Exact results belong in the release
record produced from the final release candidate; this document does not invent
benchmark or validation results.

## Known limitations

- ADE is a Technical Preview, not an operational decision system.
- Candidate findings may reflect lighting, framing, preprocessing, representation,
  or dataset effects and require human review.
- Default analysis remains the local image-folder workflow. Temporal analysis is
  separate and requires an explicit manifest and command.
- Temporal comparison does not perform geographic alignment or continuous
  ingestion.
- Fitted calibration does not create a universal anomaly probability, and a
  candidate operating point is not an automated decision threshold.
- Benchmark outputs describe the supplied validation artifact and do not establish
  general performance claims.
- Optional providers require explicit installation and configuration.

## Explicitly not included

- Hosted accounts, billing, authentication, workspace tenancy, or cloud storage.
- Continuous streams, background monitoring, or remote-imagery service integration.
- Geographic map registration or map-based review.
- Automatic domain verification or safety-critical decision authority.
- Operational support commitments, compliance certification, or service-level
  guarantees.

## Human-review boundary

ADE ranks evidence for review. A candidate anomaly, candidate concept, or candidate
temporal change is not a verified real-world conclusion. Appropriate domain experts
must review the source data, provenance, limitations, and downstream use.

## Upgrade and migration notes

This is the first `0.1.0` Technical Preview release, so there is no prior supported
release migration. Existing locally generated reports remain governed by their own
schema and validation fields. Generated demo data, reports, run indexes, dashboard
exports, benchmark outputs, and temporal artifacts should remain uncommitted.

## Verification checklist

Run from the repository root:

```powershell
ruff check
python -m mypy src
pytest
python scripts/verify_local.py
python scripts/verify_temporal_demo.py
```

For Studio frontend verification, run from `apps/studio/frontend`:

```powershell
npm --cache "D:\ADE\npm-cache" run typecheck
npm --cache "D:\ADE\npm-cache" run build
```
